# MCP 연동 기준

## 역할 분리

| 관심사 | 담당 | 원칙 |
| --- | --- | --- |
| 구매 이메일 업무 흐름, 분류, 판단, 초안 | `purchase-email-agent` Skill | 스토리보드와 기존 업무 규칙을 따른다. |
| 이메일·Ariba·파일·스프레드시트·DB 접근 | MCP Tool | 사용 가능한 도구를 먼저 발견하고 읽기와 쓰기를 구분한다. |
| 화면과 사용자 상호작용 | React/Next.js UI | 외부 시스템 연동을 위한 REST API 서버를 전제하지 않는다. |

## 현재 확인된 도구 상태

- MCP 리소스와 리소스 템플릿: 등록된 항목 없음.
- Gmail/메일 읽기·발송: 확인된 MCP Tool 없음.
- Ariba 조회·승인·반려: 확인된 MCP Tool 없음.
- 파일시스템/첨부파일·데이터베이스·과거 계약 조회: 업무 데이터에 접근하는 MCP Tool 없음.
- 문서 제어 MCP: 연결된 Excel/Sheets/문서 세션이 없으므로 사용할 수 없음.

도구명은 위 상태를 재확인한 뒤에만 사용한다. capability가 없으면 백엔드 래퍼나 REST API를 새로 만들지 말고 사용자 제공 자료로 진행하거나 필요한 자료를 요청한다.

| 스프레드시트/DB 기록 | 확정된 검토 결과 저장 | 대상, 확정 데이터, 사용자 명시 승인 | 기록 결과와 레코드 식별자 | 쓰기. 이 Skill은 실행하지 않음. |

## MCP Tool 실행 규칙

1. 현재 환경에서 실제 MCP 서버·도구·권한을 발견하고, 해당 도구의 입력 스키마를 확인한다.
2. 읽기 작업은 최소 범위의 입력을 사용한다. 도구 입력과 출력의 출처를 브리핑에 남긴다.
3. 쓰기 도구는 사용자 명시 승인 없이는 호출하지 않는다. 이 Skill의 표준 실행에서는 호출하지 않는다.
4. 도구 오류·권한 거부·빈 결과는 데이터 부재로 기록한다. 임의 추정, REST API 대체, 백엔드 래퍼 생성을 하지 않는다.
