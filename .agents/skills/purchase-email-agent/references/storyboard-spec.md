# 스토리보드 정규화 명세

이 문서는 `docs/storyboard/` 이미지에서 추출한 실행용 텍스트 명세다. 일반적인 이메일 검토에서는 이미지를 다시 읽지 않고 이 문서와 연결된 업무 규칙을 사용한다.

## 명세의 우선순위와 확인 수준

1. 사용자의 현재 지시와 실제 제공 자료
2. `SKILL.md`의 안전·증거·승인 원칙
3. 이 문서와 `references/`의 세부 업무 규칙
4. 원본 스토리보드 이미지

- **확정:** 이미지 흐름과 기존 업무 문서가 일치하는 동작
- **해석:** 이미지의 예시·메모를 일반 규칙으로 정리한 내용
- **미정:** 이미지에 기준이 없거나 제품 정책이 필요한 내용

문서끼리 충돌하거나 UI 구현·스토리보드 변경 반영·누락 분기 조사가 필요한 경우에만 관련 이미지를 확인한다. 이미지에서 새 동작을 발견하면 임의로 실행 규칙을 바꾸지 말고 확인 수준을 표시해 이 문서의 갱신 대상으로 남긴다.

## 목적과 범위

**확정:** 메일함에서 이메일을 선택하고 AI가 유형을 분류한 뒤, 구매·승인·계약 관련 메일을 구조적으로 검토하여 브리핑 또는 보완 요청 초안을 만든다. 공지와 일반 메일은 간단히 처리한다.

**확정:** 스토리보드는 분석 이후의 메일 발송, Ariba 결과 취합, 과거 데이터 조회, Excel 저장 화면까지 표현한다. 이 단계는 제품 또는 MCP Tool의 책임이며 Skill의 실행 범위가 아니다. Skill은 분석·권고·초안에서 멈춘다.

## 기본 사용자 흐름

1. 메일 브리핑 진입점에서 기간 또는 읽지 않은 메일 등 조회 범위를 선택한다.
2. 이메일 본문, 메타데이터, 스레드, 접근 가능한 첨부파일을 수집한다.
3. 전체 문맥으로 이메일 유형을 분류한다.
4. 공지·일반 업무 이메일은 중요 내용과 관련 링크를 간결히 브리핑하고 종료한다.
5. 구매 요청·구매 승인 요청·계약 관련 이메일은 본문, 첨부파일, 스레드를 분석한다.
6. 필수 정보, 기대효과, 과거 계약 비교 필요성, 위험과 미확정 사항을 검증한다.
7. 정보가 부족하면 보완 요청 이메일 초안을 작성하고 사용자 검토를 기다린다.
8. 검토가 가능하면 우선순위가 포함된 브리핑과 필요한 이메일 초안을 작성한다.
9. 실제 발송·승인·저장 등 외부 변경은 사용자 승인과 별도 실행 주체가 담당한다.

## 분류

**확정:** 다음 유형을 사용한다.

- 구매 요청
- 구매 승인 요청
- 계약 관련
- 보완 요청 또는 질의
- 공지
- 일반 업무 이메일
- 분류 불가

**해석:** 이미지의 긴급, 중요, ASAP, Immediate, Urgent, 최고 우선, 필독, 독촉, 금액, 오늘까지, 마감, Due Today, Due Tomorrow 등의 단어와 특정 수신자는 중요도 신호일 뿐 분류나 승인 권한의 확정 근거가 아니다. 전체 문맥과 요청 작업을 함께 검토한다.

**미정:** 특정 인물·직책, 금액, 키워드에 따른 자동 우선순위 및 승인 권한 정책은 정의되지 않았다.

## 구매·승인 검토 분기

### 필수 정보

**확정:** 적용 대상 필드가 부족하면 누락 항목별 보완 요청 초안을 만든다. 유형별 필드는 `field-checklist.md`를 따른다.

스토리보드가 예시로 표시한 항목은 아이템, 금액, 성과 또는 근거이며, 이를 모든 이메일에 일률적인 고정 필드로 강제하지 않는다.

### 기대효과

**확정:** 기대효과를 정량적, 정성적, 불명확, 없음으로 구분한다. 정량 주장은 수치·단위·기간·기준선·출처를 보존한다.

**해석:** 매출 증가, 비용 감소, 고객 유입, 업무 시간 절감은 기대효과의 예시다. 투자성 지출의 회수율 예시도 일반 임계값이나 자동 승인 기준으로 사용하지 않는다.

### 과거 계약 비교

**확정:** 비교가 필요하면 동일·유사 공급사와 품목, 비교 가능한 단가·총액·수량·범위·기간·납기·조건을 실제 제공 자료에서만 대조한다.

**해석:** 스토리보드는 동일 공급사, 동일 아이템, 최근 3년 이내를 이전 계약 후보의 예시 기준으로 제시한다. `최근 3년`은 조직 정책으로 확정된 기준이 아니므로 사용자 지시나 실제 조회 정책이 없으면 참고 기준으로만 쓴다.

**확정:** 자료가 없으면 조회했다고 가정하지 않고 `과거 계약 비교 필요 — 비교 자료 미제공 — 사용자 또는 시스템 조회 필요`로 표시한다.

## 논의 이메일과 첨부파일

**확정:** 구매·Ariba 공지나 단순 안내가 아니라 문의, 논의, 견적 등의 내용이면 논의 이메일 경로로 처리한다.

1. 첨부파일 제공 여부와 접근 가능성을 확인한다.
2. 접근 가능하면 첨부파일을 본문과 별도로 분석하고 서로 대조한다.
3. 스레드를 최초 요청, 주요 논의, 결정, 미결 사항, 담당자, 기한으로 요약한다.
4. 필요하면 과거 저장 자료 비교 필요성을 판단한다.
5. 결과를 구매 검토 브리핑에 합친다.

첨부파일이나 링크가 언급됐지만 접근할 수 없으면 분석한 것처럼 작성하지 않는다.

## 제품 및 외부 시스템 경계

스토리보드에 표현된 다음 단계는 제품 요구사항이지만 Skill이 직접 수행하지 않는다.

| 단계 | 담당 | Skill의 처리 |
| --- | --- | --- |
| 메일 목록·기간·읽지 않음 필터 | UI 및 이메일 읽기 MCP | 제공되거나 조회된 입력만 분석 |
| 보완 요청·검토 메일 발송 | 이메일 쓰기 MCP 또는 제품 | 초안 작성 후 사용자 승인 대기 |
| Ariba 결과 취합·승인·반려 | Ariba MCP 또는 제품 | 검토 브리핑만 제공 |
| 과거 계약·구매 데이터 검색 | 읽기 MCP | 실제 결과만 비교 근거로 사용 |
| 기존 레코드 분석·신규 레코드 생성 | 데이터 저장 계층 | 기록 후보를 제안할 수 있으나 쓰지 않음 |
| Excel 저장 및 완료 메시지 | 문서 MCP 또는 제품 | 저장하지 않음 |
| 과거 데이터 비교 분석 화면 | UI | 비교 결과를 구조화해 제공 |

외부 쓰기는 사용자 명시 승인, 사용 가능한 도구, 검증된 입력이 모두 있어야 하는 제품 단계다. 이 Skill은 승인이 있어도 실제 쓰기 작업을 수행하지 않는다.

## 출력과 완료 조건

**확정:** 구매 이메일 검토 결과에는 중요한 순서의 요약, 확인된 사실, 추론, 누락 정보, 사용자 확인 필요, 기대효과, 과거 계약 비교 상태, 권장 다음 단계가 포함된다. 필요할 때만 이메일 초안을 포함한다.

**해석:** 여러 이메일을 한 번에 브리핑하는 제품 화면에서는 구매 승인 요청을 우선 노출하고 세금·tax 등의 업무 키워드 및 지급기일 초과 여부를 보조 신호로 활용할 수 있다. 구체적인 정렬 공식은 미정이다.

분석 완료는 브리핑 또는 초안이 준비된 상태다. 발송, 승인, 외부 저장의 성공을 Skill 완료 조건으로 간주하지 않는다.

## 원본 이미지 확인 조건

다음 경우에만 `docs/storyboard/overview.png` 또는 관련 분할 이미지를 연다.

- 사용자가 이미지 자체의 검토·수정·UI 구현을 요청함
- 스토리보드 이미지가 변경되어 이 문서에 반영해야 함
- 이 문서와 다른 업무 규칙 사이에 해결되지 않은 충돌이 있음
- 요청된 분기나 화면 동작이 텍스트 명세에 없음

일반 이메일 분류, 정보 추출, 검증, 브리핑, 초안 작성에서는 이미지를 열지 않는다.
