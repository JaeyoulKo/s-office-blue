# 우선순위 판정 규칙

원본은 스토리보드의 `구매승인 요청 이메일 우선순위 판별` 스티커다.
기계 판독본은 [`docs/user-flow/criteria.yaml`](../../../docs/user-flow/criteria.yaml)의
`briefing_priority`.

## 티어 — 위에서부터 순위를 채운다

같은 티어 안에서는 **금액이 큰 순**, 금액이 같거나 없으면 **기한이 이른 순**으로 정렬한다.

| 티어 | 조건 | 근거 |
| --- | --- | --- |
| **T1** | `지급기일 초과` / `연체` / `overdue` / `past due` 키워드 | 스티커: 지급기일 초과 키워드 포함 |
| **T2** | `세금` / `tax` / `세금계산서` / `부가세` 키워드 | 스티커: 세금, tax 키워드 포함 |
| **T3** | `important` 로 분류된 메일 | 사람이 지금 봐야 하는 것 |
| **T4** | `ariba_approval` 중 금액 상위 5건 | 스티커: 금액순 top5 |
| **T5** | 명시된 `deadline`이 오늘·내일인 나머지 | 마감 임박 |
| **T6** | 나머지 `ariba_approval`, `discussion` | |
| **—** | `notice`, `unknown` | `priority_rank`는 `null` |

`unknown`은 순위를 매기지 않는다. 무엇인지 모르는 것에 순서를 주면 그 판단까지 틀린다.
대신 `notes`에 확인이 필요하다고 남긴다.

## 티어가 겹칠 때

한 메일이 T1과 T2에 동시에 걸리면 **더 위 티어를 따른다.**
`[긴급] 3분기 세금계산서 지급기일 초과 건`은 T1이다.

`priority_reason`에는 **적용된 티어와 근거 키워드**를 밝힌다.

- 좋음: `지급기일 초과 키워드(T1), 금액 12,000,000원`
- 나쁨: `중요해 보임`

## 금액 정규화

| 표기 | `amount_krw` |
| --- | --- |
| `₩12,000,000` / `12,000,000원` | `12000000` |
| `1,200만원` / `1200만 원` | `12000000` |
| `1.2억` | `120000000` |
| `USD 5,000` / `$5,000` | `null` — 환산하지 않고 `notes`에 기록 |
| `약 1천만원 내외` | `null` — 확정 금액이 아니다 |
| 미기재 | `null` |

`amount_krw`가 `null`인 `ariba_approval`은 T4의 "금액 상위 5건"에 들어갈 수 없다.
T6으로 내리고 `notes`에 `금액 미기재 — 확인 필요`를 남긴다.
금액을 모르는 건을 상위로 올리면 진짜 고액 건이 밀려난다.

## 기한 환산

메일의 `date`를 기준으로 Asia/Seoul 기준 환산한다.

| 표현 | 결과 |
| --- | --- |
| `오늘까지`, `Due Today` | 메일 `date`의 날짜 |
| `내일까지`, `Due Tomorrow` | 메일 `date` + 1일 |
| `8/15까지` | 메일 연도를 붙여 `YYYY-08-15` |
| `이번 주 내` | `null` — 특정 날짜가 아니다 |
| `가능한 빨리`, `ASAP` | `null` — 날짜가 아니다. 단 T3 판정 신호로는 쓴다 |
