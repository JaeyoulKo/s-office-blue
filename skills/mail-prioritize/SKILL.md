# 우선순위 판별

## 목적

분류된 메일에 **처리 순서**를 매기고, 순위 판단에 쓰인 값(`amount_krw`, `deadline`, `owner`)을
본문에서 추출한다. `mail-classify` 다음에 수행한다.

## 절차

1. **추출 먼저, 순위는 나중에.** 각 메일에서 금액·기한·담당자를 먼저 뽑는다. 없으면 `null`이다.
2. **[references/rules.md](references/rules.md)의 규칙**으로 각 메일의 급함을 판정한다.
3. **전체를 한 줄로 세운다.** `priority_rank`는 스냅샷 전체에 걸쳐 1부터 시작하는 연속된 정수다. 동점을 만들지 않는다.
4. **순위가 필요 없는 메일은 `null`이다.** `notice`는 보통 `null`이고, `priority_reason`은 빈 문자열이다.
5. **각 순위마다 이유를 한 문장으로** `priority_reason`에 적는다. 어느 규칙이 걸렸는지 밝힌다.

## 추출 규칙

**`amount_krw`** — 본문에 **명시된** 금액을 원 단위 정수로.

- `₩12,000,000` → `12000000`
- `1,200만원` → `12000000`
- `USD 5,000` → `null` (환율을 임의로 적용하지 않는다. `notes`에 원화 아님을 남긴다)
- 금액 언급이 없으면 `null`. **추정 금지.**

**`deadline`** — 명시된 기한을 `YYYY-MM-DD`로.

- `오늘까지`, `내일까지` 같은 상대 표현은 메일의 `date`를 기준으로 환산한다 (시간대 Asia/Seoul)
- `가능한 빨리`, `조속히` → `null`. 날짜가 아니다
- 없으면 `null`

**`owner`** — 본문에서 확인되는 담당자.

- 본문에 이름/부서가 명시된 경우만
- 발신자를 담당자로 자동 간주하지 않는다
- 없으면 `null`

## 지어내지 않기

추출은 **읽어내는 것**이지 추론하는 것이 아니다.
금액이 안 적힌 승인 요청은 "보통 이 정도"로 채우지 말고 `null`로 두고,
`notes`에 `금액 미기재 — 확인 필요`를 남긴다. **빈칸이 틀린 값보다 낫다.**

## 자체 검토

1. 금액 없는 승인 요청 → `amount_krw`가 `null`이고 `notes`에 기록됐는가.
2. `notice`만 있는 스냅샷 → `priority_rank`가 전부 `null`이어도 정상이다.
3. `priority_rank`에 중복된 숫자가 없는가.
4. `지급기일 초과` 건이 단순 고액 건보다 앞에 있는가.
