# 논의 이메일 판단 규칙

## 논의 메일 신호

- 기존 구매·계약 건에 대한 질문, 설명 요청, 이견, 조건 협의 또는 추가 자료 요청이 중심임
- 여러 참여자가 같은 건을 회신하며 결정과 미결 사항이 함께 존재함
- 견적서·계약서·스프레드시트 등 첨부파일과 본문을 대조해야 함

`Re:`, `Fwd:`, 긴 스레드, 첨부파일 존재만으로 논의 메일을 확정하지 않는다. 실제 요청
의도와 문맥을 확인한다.

## 스레드 요약 단위

1. 최초 요청과 건의 목적
2. 시간순 주요 논의
3. 확인된 결정과 그 근거
4. 해결되지 않은 질문과 모순
5. 담당자가 명시된 작업
6. 원문에 명시된 기한

발신자와 수신자를 승인권자로 자동 해석하지 않는다. 특정 직책, 금액, 긴급 키워드에 따른
권한과 우선순위 정책은 사용자 확인 사항으로 둔다.

## 첨부파일과 과거 자료

첨부파일이 언급되었지만 접근할 수 없으면 `첨부파일 미확인`으로 표시한다. 접근 가능한
파일만 분석하고 본문과 다른 값은 임의로 하나로 합치지 않는다. 과거 자료 매칭은 공급사,
품목, 스레드 문맥, 사용자가 제공한 식별자를 근거로 하며 불확실한 매칭은 추론으로 남긴다.

## 회신 판단

- 질문에 답할 근거가 충분하면 `답변 가능`
- 첨부파일, 값 또는 설명이 더 필요하면 `추가 자료 필요`
- 정책, 승인 권한, 해결되지 않은 이견이 있으면 `사용자 판단 필요`
- 실제로는 새 구매 요청이나 공지에 가까우면 `분류 재확인 필요`

회신 초안은 확인된 결정, 남은 질문, 다음 작업을 분명히 구분한다. 제공되지 않은 수신자,
약속, 기한, 승인 표현을 추가하지 않는다.
