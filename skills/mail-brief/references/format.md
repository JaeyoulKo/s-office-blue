# 브리핑 형식

스토리보드의 `브리핑 화면` 노드와 `검토 결과 금액순 요약 및 링크 전달` 스티커에서 왔다.

## summary 골격

```
[기간/범위] 총 N건.
먼저 볼 것: <1순위 제목> — <이유>.
승인 요청 M건 (합계 ₩X). 논의 K건. 공지 P건.
확인 필요: <미확인 항목이 있으면>.
```

없는 줄은 **생략한다.** 빈칸을 남기거나 `해당 없음`으로 채우지 않는다.

## 예시

### 처리할 것이 있을 때

```
지난 7일 안 읽은 메일 18건.
먼저 볼 것: [긴급] 3분기 세금계산서 지급기일 초과 건 — 지급기일이 지났습니다.
승인 요청 5건 (합계 ₩41,200,000). 논의 3건. 공지 9건.
확인 필요: 승인 요청 1건에 금액이 적혀 있지 않습니다.
```

### 처리할 것이 없을 때

```
지난 7일 안 읽은 메일 6건. 모두 공지·안내입니다.
처리가 필요한 메일이 없습니다.
```

이게 정답이다. 분량을 만들려고 공지를 요약해 늘리지 않는다.

### 분류가 안 된 것이 있을 때

```
지난 7일 안 읽은 메일 12건.
먼저 볼 것: [Action Required] PR-1055 결재 요청 — 금액 ₩12,000,000, 기한 08-11.
승인 요청 3건. 공지 7건.
확인 필요: 2건은 본문이 비어 있어 분류하지 못했습니다.
```

**`unknown`은 반드시 요약에 드러난다.** 브리핑만 읽는 사람이 놓치면 안 되기 때문이다.

## 금지

| 쓰지 않는다 | 왜 |
| --- | --- |
| `승인하셔도 될 것 같습니다` | 판단은 사람의 몫이다 |
| `총 약 4천만원 규모` | `amount_krw` 합계와 어긋난다. 정확한 값을 쓴다 |
| `중요한 메일이 여러 건 있습니다` | 숫자로 쓴다 |
| `자세한 내용은 각 메일 참조` | 아무 정보가 없는 줄이다 |
| 원문에 없는 회사명·담당자·프로젝트명 | 환각이다 |

## top_items 의 why

`priority_reason`은 규칙 기록("T1, 지급기일 초과 키워드")이고,
`why`는 사람이 읽는 문장("지급기일이 지났습니다")이다. 사실은 같아야 한다.

| priority_reason | why |
| --- | --- |
| `지급기일 초과 키워드(T1), 금액 12,000,000원` | `지급기일이 지난 12,000,000원 건입니다.` |
| `발신인 CFO(T3)` | `CFO가 직접 보낸 메일입니다.` |
| `금액 상위(T4), 38,000,000원` | `이번 목록에서 가장 큰 금액의 승인 요청입니다.` |
