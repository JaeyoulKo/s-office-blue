# 브리핑 생성

## 목적

`briefing` 블록을 채운다. 스토리보드의 `메일 종류별 갯수 카운트, 우선 순위 판별 및 요약 작성`
→ `브리핑 화면`에 해당한다. `mail-classify`와 `mail-prioritize` 다음에 수행한다.

## 절차

1. **`counts`를 센다.** 라벨 다섯 개 각각의 건수. **합계가 스냅샷의 메일 수와 반드시 같아야 한다.**
2. **`top_items`를 고른다.** `priority_rank`가 `null`이 아닌 것 중 순위 오름차순으로 **최대 5건**. 순위가 매겨진 메일이 5건 미만이면 있는 만큼만 넣는다. 채우려고 `notice`를 끌어오지 않는다.
3. **`why`를 쓴다.** 각 항목마다 왜 먼저 봐야 하는지 한 문장. `priority_reason`을 그대로 복사하지 말고 사람이 읽을 문장으로 바꾸되, 사실은 바꾸지 않는다.
4. **`summary`를 쓴다.** [references/format.md](references/format.md)의 형식을 따른다.

## summary 규칙

**30초 안에 읽힌다.** 5줄 이내, 각 줄은 짧게.

- **사실만 쓴다.** 브리핑은 판단하는 자리가 아니다. `승인하는 것이 좋겠습니다` 같은 문장을 쓰지 않는다.
- **숫자는 `counts`·`amount_krw`와 일치해야 한다.** 본문 어디에도 없는 숫자를 만들지 않는다.
- **비어 있으면 비어 있다고 쓴다.** 처리할 메일이 없으면 `처리가 필요한 메일이 없습니다`가 정답이다. 억지로 분량을 만들지 않는다.
- **미확인 항목을 숨기지 않는다.** `unknown`이 있거나 금액 미기재 건이 있으면 요약에 그 사실이 드러나야 한다. 브리핑만 읽는 사람이 그것을 놓치면 안 된다.

## 자체 검토

1. `counts` 합계 == 스냅샷 메일 수인가.
2. `top_items`의 모든 `message_id`가 `items`에 존재하고 `priority_rank`가 `null`이 아닌가.
3. `top_items`가 순위 오름차순인가.
4. `summary`의 숫자가 `counts`와 어긋나지 않는가.
5. `unknown`이 1건 이상인데 `summary`가 그것을 언급하지 않는다면 다시 쓴다.
