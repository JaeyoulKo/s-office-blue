# 이메일 분류 판단 규칙

## 분류 유형

- `구매 승인 검토 필요 이메일`: 사람이나 팀에 구매, Ariba 작업, 지출 또는 이에 준하는 결정을 승인해
  달라고 요청한다.
- `논의 내용 요약 필요 이메일`: 계약, 구매 또는 지출 건의 변경, 조건, 상태, 쟁점, 미결 사항이나 다음 결정을 논의한다. 스레드의 최초 값과 최신 값이 다르거나 기존 결정의 유효성을 다시 확인해야 하는 경우를 포함한다.
- `일반 이메일`: 위 두 유형이 아닌 업무 메일이다. 공지, 단순 안내, 이미 처리된 건의 정정·재제출 사실 통보를 포함한다.

`Action Required`, `Ariba`, `ASAP`, `approval`, `purchase`, 긴급 표현, 금액, 특정 수신자는
보조 신호일 뿐 확정 근거가 아니다. 전체 스레드의 의도와 실제 요청 작업을 함께 검토한다.

이미 승인된 PR의 벤더명 등 오기입을 정정해 재제출했다는 사실만 알리고 새 승인이나 검토를
요청하지 않는 메일은 `일반 이메일`이다. `PR`, `승인`, `재제출`이라는 표현만으로
`구매 승인 검토 필요 이메일`로 분류하지 않는다.

## 증거 구분

- `확인된 사실`: 제공된 이메일, 메타데이터, 첨부파일 또는 읽기 결과에서 직접 확인됨
- `추론`: 확인된 사실에 근거하지만 원문에 직접 쓰이지 않은 판단
- `누락 정보`: 분류 또는 다음 작업에 필요하지만 제공되지 않은 정보
- `사용자 확인 필요`: 사람의 판단, 정책 해석, 승인 또는 외부 작업이 필요한 사항

키워드, 첨부파일 언급, 접근할 수 없는 링크를 확인된 사실로 바꾸지 않는다. MCP Tool 오류,
권한 없음, 빈 결과도 사실이 확인된 것으로 처리하지 않는다.

## 긴급도 판단

`urgency`는 분류와 별개로, 이 메일을 얼마나 먼저 처리해야 하는지를 `high`, `medium`, `low`로
남긴다.

- `high`: 확인 가능한 원화 금액이 5억원 이상이거나, 지급 기일이나 마감을 이미 넘겼거나,
  같은 건에 대한 반복 독촉이거나, 처리가 늦어지면 되돌리기 어려운 결과가 생긴다고 원문에서
  확인된다.
- `medium`: 명시된 기한이 임박했거나, 세금·정산처럼 시점이 정해진 절차가 걸려 있거나,
  발신자가 다음 작업을 위해 이 답을 기다리고 있다.
- `low`: 위에 해당하는 근거가 원문에 없다.

`긴급`, `ASAP`, `urgent`, `즉시` 같은 단어는 신호일 뿐 그 자체로 `high`의 근거가 아니다.
금액은 원문 또는 구조화된 입력에서 통화와 함께 확인된 값만 사용한다. 원화 5억원 이상은
`high`로 두며, 외화는 제공된 환율 근거가 없으면 원화로 환산하거나 금액만으로 긴급도를 올리지
않는다. 원문에 없는 금액, 기한이나 지연 사실을 추정하지 않는다.

## 분류 후 처리

- `구매 승인 검토 필요 이메일`은 `purchase-email-review` 검토 대상으로 넘긴다.
- `논의 내용 요약 필요 이메일`은 `discussion-email-review` 검토 대상으로 넘긴다.
- `일반 이메일`은 핵심 내용과 실제 요청 작업만 간결하게 브리핑한다.
