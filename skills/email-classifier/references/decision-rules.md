# 이메일 분류 판단 규칙

## 분류 유형

- `구매 승인 요청`: 사람이나 팀에 구매, Ariba 작업, 지출 또는 이에 준하는 결정을 승인해
  달라고 요청한다.
- `구매 요청`: 상품이나 서비스의 구매·소싱·주문을 요청하지만 주 목적이 승인은 아니다.
- `계약 관련`: 계약 조건, 체결, 변경, 갱신, 해지 또는 협상을 중심으로 한다.
- `보완 요청 또는 질의`: 기존 건의 누락 사실, 설명, 의견 또는 결정을 요청하는 것이 주
  목적이다.
- `공지`: 실질적인 작업 요청이 없는 일방적인 안내다.
- `일반 업무 이메일`: 위 유형 밖의 업무 메일이다.
- `분류 불가`: 자료가 너무 불완전하거나 상충되어 책임 있게 분류할 수 없다.

`Action Required`, `Ariba`, `ASAP`, `approval`, `purchase`, 긴급 표현, 금액, 특정 수신자는
보조 신호일 뿐 확정 근거가 아니다. 전체 스레드의 의도와 실제 요청 작업을 함께 검토한다.

## 증거 구분

- `확인된 사실`: 제공된 이메일, 메타데이터, 첨부파일 또는 읽기 결과에서 직접 확인됨
- `추론`: 확인된 사실에 근거하지만 원문에 직접 쓰이지 않은 판단
- `누락 정보`: 분류 또는 다음 작업에 필요하지만 제공되지 않은 정보
- `사용자 확인 필요`: 사람의 판단, 정책 해석, 승인 또는 외부 작업이 필요한 사항

키워드, 첨부파일 언급, 접근할 수 없는 링크를 확인된 사실로 바꾸지 않는다. MCP Tool 오류,
권한 없음, 빈 결과도 사실이 확인된 것으로 처리하지 않는다.

## 분류 후 처리

- 공지와 일반 업무 이메일은 핵심 내용과 실제 요청 작업만 간결하게 브리핑한다.
- 구매 요청, 구매 승인 요청, 계약 관련은 `purchase-email-review` 검토 대상으로 넘긴다.
- 보완 요청 또는 질의와 긴 논의 스레드는 `discussion-email-review` 검토 대상으로 넘긴다.
- 분류 불가는 상충 신호와 추가로 필요한 자료를 적고 사용자 확인을 요청한다.
